### Plain answer

**Wired: mostly yes. Connected: yes for what was tested. Functional: not proven, and one live path is demonstrably broken.** The five live routes (/finder, /chart, /paper, /settings, /login) call 49 distinct API routes, and every one of those exists in the route table, with one exception: `KLineChartOverlay.tsx:321` requests `GET /api/patterns/{symbol}/elliott-waves`, which matches no route (static finding; I did not curl it, so I cannot say how the UI degrades). None of the four 500s or the 422 is reachable from the live UI: all five are API-ONLY or DELETE-CANDIDATE. But three WIRED routes were slow or failed in the smoke test: `/api/finder/scan/wide` (the Finder "wide" preset) hit a ReadTimeout above 25s, `/api/crypto-signals/scan` (Finder crypto preset) took 15.5s, and `/api/command-center` took 9.1s and is polled by the layout (`components/alerts/AlertManager.tsx:135 via useCommandCenter (hooks.ts:309) (+1 more)`). Uvicorn runs one worker, so each of those freezes the whole API for its duration, including the other live pages. Finally, the WIRED parameterised routes (most of what the Chart page calls) were never smoke-tested, so "functional" is unknown for them. Separately, 27 routes (DELETE-CANDIDATE) exist only for pages deleted in 45c8615, and 98 API-ONLY routes have no UI caller at all.

## Method and caveats

- **Route table**: taken from the running app's `app.routes` (174 entries, `/api/*`), with the decorator line from `inspect.getsourcelines`. Matches the 173 decorators + `/api/health`.
- **Callers**: statically extracted from `frontend/src` (regex over `api.get/post/...`, `axios.*`, `fetch(...)`, and `guarded(...)` in PaperTradingPage), with `${const}` substitution, then matched to routes by method and path segments (literal segments beat path params). Hook calls are attributed to the files that call the hook. Static analysis only: no runtime tracing, and dynamic URLs I could not resolve (only TradesPage, handled by hand) are the main blind spot.
- **Live** = file reachable from `frontend/src/main.tsx` through relative imports in the working tree. A call in a present-but-unreachable file does not count as WIRED.
- **WIRED**: at least one live caller. **DELETE-CANDIDATE**: no live caller, and every consumer found at 45c8615^ (the commit before the page deletion), at HEAD, and in the working tree is one of the 24 page files deleted in 45c8615 (directly, or through a hook only those pages used). Consumers that were components or pages *other* than those 24 (for example TradesPage, TradeLogger, WatchlistPanel) do **not** qualify, even if they are now deleted: they are API-ONLY with the former consumer named. **API-ONLY**: everything else.
- **Commit 45c8615 count**: the commit title says 25 pages; its diff stat lists 24 files, and this inventory uses the 24.
- **Already-dead before 45c8615**: the 24 deleted pages were unreachable from `App.tsx` even at 45c8615^ (routes had been cut to three in 821d621), so "deleted page" means "dead for some time", not "recently live".
- **Concurrent deletion**: another worker deleted ~24 frontend modules in this worktree while this ran (staged `D` entries, `MacroContext.tsx` added, SideNav/MacroTickerBar/TerminalLayout modified). The working-tree figures reflect the tree at the time of analysis (27 files under `frontend/src`). Re-run if that work continues.
- **API-ONLY reasons**: only three kinds are verified: the in-process scheduler POSTs `/api/pipeline/run` (api/main.py, off by default), auto-trader routes that `docs/AUTO_TRADER.md` documents for operator use, and routes whose only caller is an unused hook. For all others the row says "intent NOT verified". I did not establish whether any external consumer, Celery job, or ops tool uses them.
- **Smoke results** are the coordinator's run of 83 parameterless GETs; I reproduced only the five failures above.
